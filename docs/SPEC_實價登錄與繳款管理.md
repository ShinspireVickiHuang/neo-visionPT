## 一、實價登錄管理

### 1.1 業務背景與職責分工

預售屋成交後，依實價登錄 2.0 規定須於**簽約日起 30 天內**完成申報，逾期有罰則。
本模組把職責切成三段，避免多頭維護：

| 角色 | 負責 | 操作位置 |
|------|------|----------|
| 業務 | 填簽約日期（唯一輸入） | 銷控表 → 戶別編輯 |
| 系統 | 簽約 +25 天自動通知該建案的業務與專案 | 後端排程 |
| 行政 | 登錄實際登錄日期＋實價登錄序號 | 實價登錄狀況表 |

**設計原則**：銷控表不出現任何實價登錄欄位（避免業務誤填）；登錄資料的唯一維護入口是實價登錄狀況表。

### 1.2 銷控表（sales-control.html）的變更

- 戶別編輯彈窗**不含**應登錄日期／實際登錄日期／實價登錄序號
- 填寫簽約日期後，即時顯示藍色提醒框：
  - 通知日＝簽約日 +25 天（顯示實際日期）
  - 說明文字：系統將自動通知本建案的業務與專案；登錄作業由行政至「實價登錄狀況表」執行

### 1.3 實價登錄狀況表（declaration-status-list.html）

選單位置：銷控管理 → 實價登錄狀況表。

#### 資料來源
銷控已成交戶。**所有權人（＝購買人姓名）與簽約日期必有值**；未售戶不會出現在本表。

#### 列表欄位
建案｜棟-戶-樓｜客戶姓名｜成交價(萬)｜業務員｜簽約日期｜**通知日(+25天)**｜**應登錄日期(+30天)**｜實際登錄日期｜實價登錄序號｜登錄狀態｜操作

#### 登錄狀態（系統自動判定，不可人工指定）

| 狀態 | 判定規則 | 顯示 |
|------|----------|------|
| 已登錄（準時） | 有實際登錄日，且 ≤ 應登錄日 | 綠 |
| 已登錄（逾期） | 有實際登錄日，但 > 應登錄日 | 橘 |
| 未登錄・已逾期 | 無實際登錄日，且今日 > 應登錄日 | 紅 |
| 未登錄・期限內 | 無實際登錄日，今日 ≤ 應登錄日 | 灰 |
| 已解約 | 有解約註記（優先於其他判定） | 黑 |

#### 自動通知（+25 天）
- 通知日＝簽約日 +25 天（法定 30 天的內部提前線）
- 通知對象＝該戶業務＋該建案專案負責人
- 通知日已到且尚未登錄者，列表標示「已自動通知業務/專案」
- 已解約戶不通知

#### 手動通知
- 未登錄戶操作欄有「通知」按鈕，不必等排程隨時可催辦
- 通知對象預設勾選業務＋專案，可個別取消
- 通知訊息預帶催辦文字（含戶別與應登錄期限），可修改
- 每次發送留存紀錄（日期、對象、訊息）；列表顯示「手動通知 N 次（最後日期）」

#### 行政登錄
- 操作欄「登錄」開彈窗：實際登錄日期（必填、不可早於簽約日）＋實價登錄序號（必填）
- 已登錄者按鈕變「修改登錄」，可更正
- 儲存後狀態與統計即時重判

#### 解約註記
- 實務：解約另案向地政機關辦理**解約申報**；原申報紀錄僅資料留存
- 系統上只做**註記**：解約日期（必填、不可早於簽約日）＋解約備註（建議註明原因與解約申報辦理狀態）
- 註記後：原實際登錄日期與序號**留存不刪**；整列淡化＋黑色「已解約」標籤；退出逾期判定；通知與登錄按鈕收起
- 「已解約」可作為搜尋條件，統計表含「已解約」欄
- 註記錯誤可「取消解約註記」（confirm 後恢復依日期判定）

#### 搜尋與統計
- 搜尋條件：建案（下拉）、客戶姓名、業務員、登錄狀態（下拉，含已解約）、簽約日期區間、「僅顯示待辦」快篩
- 統計：按「搜尋」後才顯示；**依建案分組**：成交戶數｜準時｜逾期登錄｜未登錄已逾期｜未登錄期限內｜已解約，含總計列
- 匯出按鈕（匯出目前查詢結果）

## 二、繳款管理

選單結構：

```
繳款管理（頂層選單）
├─ 繳款紀錄管理（house-management.html）
└─ 繳款期別管理（payment-schedule-management.html）
```

整體資料流：**期別管理設定範本 → 建案套用 → 各戶依範本自動展開期別 → 逐期登錄繳款**。

### 2.1 繳款期別管理

#### 期別範本
- 一組範本＝付款辦法：範本名稱＋期別明細（期別名稱、繳款比例 %、應繳時點）
- 應繳時點為規則描述：可推算型（「下訂當日」「簽約後 N 天」）與工程節點型（「開工日」「結構體完成」等）
- **比例合計檢查**：＝100% 顯示綠色；≠100% 紅字警告「未達 100%，請檢查」（收合狀態也可見）
- 範本卡**預設收合**（摘要列：名稱／期數／合計%／已套用建案數），點標題展開明細；搜尋重繪保留展開狀態
- 操作：新增範本（期別可逐列增刪）、編輯、複製

#### 套用到建案（為數百建案的量級設計）
- 範本卡只顯示「已套用 N 個建案」＋「查看清單」（彈窗內可搜尋）
- 套用採**先搜尋再勾選**：輸入建案關鍵字才列出符合建案，不整頁展開
- 每個建案顯示目前套用狀態：已套用本範本／目前套用：某範本／尚未套用範本
- **一案一範本**：勾選已套用其他範本的建案，儲存時跳確認「將改套用本範本，確定覆蓋嗎？」
- 搜尋條件：範本名稱；**建案名稱反查**（輸入建案名 → 顯示它套用的範本；未套用者紅字提示）

### 2.2 繳款紀錄管理

#### 資料來源與邊界
- 列表＝銷控**已售出**戶別；**無新增、無刪除**（資料源頭在銷控）
- 所有權人＝購買人姓名，由銷控帶入唯讀
- 搜尋條件：建案（下拉）、戶別、備註關鍵字；匯出
- 列表欄位：建案｜戶別｜所有權人｜簽約日期｜操作（戶別款項、合約及附件管理）

#### 戶別款項（模組核心）

**期別自動展開**
- 期別依建案套用的範本自動產生：應繳金額＝**原合約總價 × 各期比例%**
- 最後一期自動吸收四捨五入尾差，合計必等於原合約總價
- **尾差吸收僅發生在自動展開時**；金額被人工調整後，系統不自動重算其他期別，由使用者自行調整至平衡（見下方對帳防呆）
- 應繳日期可推算者自動算（下訂當日＝簽約日；簽約後 N 天）；工程節點顯示規則文字
- 建案未套用範本 → 提示並附「繳款期別管理」連結

**追加款（總價中途變動的處理）**
- 原則：**已有繳款紀錄的期別受保護**——任何調整不得使該期應繳金額低於已繳實繳金額（見對帳防呆②）；任何追加不回頭改原期別的預設拆分
- 車位加購：銷控加購車位時**自動同步**產生「車位加購款」（應繳日＝加購日 +7 天），標示「銷控自動同步」，**不可在本模組刪除**；車位退訂在銷控操作，系統監聽退訂事件自動沖銷對應期款（保留軌跡，見開發文件 §3.4）
- 客變追加／其他：以「新增期款」手動登錄——款項類型（必選：客變追加／其他／車位加購**僅供補登**，正常情況車位加購由銷控自動同步）、期款名稱（不可與既有期別重複）、應繳日期、應繳金額（>0）、事由（必填）
- 手動新增的期款**可刪除**；刪除前 confirm 顯示對帳確認（應繳總額變化）；已有繳款紀錄者強確認（連同繳款紀錄一併移除）

**金額調整與對帳防呆**
- 各期應繳金額可直接編輯（含範本期別）；調整過的期別標「已調整」
- **對帳錨點＝原合約總價（銷控帶入，不可改）**
- 平衡列即時顯示：**原合約期別（範本展開的期別，不含追加款）加總 vs 原合約總價**，含差額；追加款合計另計；應繳總額＝原合約期別加總＋追加款合計
- 防呆：①不平衡（原合約期別加總≠原合約總價）擋儲存 ②任何期別應繳金額不可低於已繳實繳金額

**排序與儲存**
- 期別列可**拖拉排序**（列首 ⠿ 把手）
- 「儲存」統一寫入：順序＋金額調整；未儲存關閉跳確認「確定放棄變更？」

**登錄繳款**
- 未繳清期別有「登錄繳款」：實繳日期（必填）、實繳金額・累計（必填 >0）、繳款方式（匯款/支票/現金/刷卡，必填）、備註、**繳款證明上傳**（圖片/PDF、可多張、累加不覆蓋）
- 證明檔顯示於明細備註欄（📎 檔名，可下載）

**繳款狀態（自動判定）**

| 狀態 | 規則 |
|------|------|
| 已繳 | 實繳累計 ≥ 應繳 |
| 部分繳 | 0 < 實繳累計 < 應繳 |
| 逾期未繳 | 未繳且今日 > 應繳日 |
| 未到期 | 未繳且今日 ≤ 應繳日（或無應繳日） |

**摘要卡**：應繳總額（顯示「原合約 X＋追加 N 筆 Y」結構）｜已繳金額｜未繳金額｜繳款進度 %

#### 合約及附件管理（已合併原編輯功能）
- 戶別資訊區：建案／戶別／所有權人／簽約日期／車位號碼／合約總價／房屋金額／每坪單價／車位金額——全部**銷控帶入唯讀**
- 可維護欄位：合約代碼、備註
- 附件清單：檔名／類型／上傳日期／上傳人／操作（下載、刪除）＋上傳附件

## 三、通用設計原則（兩模組共用）

1. **資料源頭唯一**：來自銷控的欄位一律唯讀帶入；要改回源頭改（車位退訂回銷控、成交資料回銷控）
2. **狀態一律系統判定**：登錄狀態、繳款狀態不開放人工指定，杜絕狀態與資料不一致
3. **不可逆動作留跡**：通知有紀錄、期款刪除有對帳確認、解約有註記與備註
4. **量級思維**：建案數百案（套用採搜尋式）、範本數十組（預設收合）、戶別數千戶（統計依建案分組）
